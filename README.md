# Church-Sound-Board-Communication
This will be an application that can be downloaded onto devices and will connect to a central server. It will be a communication device to relay important details. 

## Ideas
+ I am thinking that this will be an application that would allow for musicians to be able to communicate with the sound board team with the tap of a button. 
+ Should it be set up to let you log in as a certain type of mucision. An Example is if you are at the drumms you can set that so all communication will just tell the soundboard who you are, without you saying. Or if you are on piano it would be the same. 
+ Sound Board would be the server that everyone connects to. It would be able to communicate with the individuals or the entire team. And be able to receive information. 
+ You can set yourself as the leader and would it make sense to be able to view what your team is requesting? But not have it be a main page. 
+ All ran localy. Nothing is stored in a cloud. (I don't think anything should be stored anyways.)
### Things you can communicate
+ More or less volume of each type of positions, instrumants, singers, or leaders. (maybe even more detailed request for guitar, bass, piano, etc...)
+ Some form of communication about questions. probably basic questions such as, how many bridges, build, what song? (I want it to be very limited typing. manly buttons)
### Design
+ It to be a very simple design. Manly buttons with images to keep it easy to see for all ranges of eye sight. 
+ No typing. (besides from the server/soundboard) 
+ color cordination. 
### Requirments 
+ quick load times to make sure that communications are happening live. 
+ Low CPU loud. Making sure that the server isn't eating to much run time on a computer already having a lot running on it. 
+ Easy to use.
